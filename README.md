# Supabase game library

A Next.js app that fetches `id`, `name`, and `genre` from the existing Supabase `public.games` table and renders them as cards on `/`. Each request fetches the current rows, ordered by ID. Loading, empty, and error states are included.

## Local setup

1. Install dependencies with `npm install`.
2. Copy `.env.example` to `.env.local` if you do not already have one.
3. Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` to your project's URL and anon key. The app also supports `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (the existing local configuration). Use a public key, never a service-role key.
4. Run `npm run dev` and visit http://localhost:3000.

`.env.local` is ignored by Git. Credentials are read from environment variables in `lib/supabase.ts`, never hardcoded. Configure the same environment variables in your deployment environment.

## Database

The connected project already has a `games` table with four rows. No migration is needed for that project. For a new project, run the following in Supabase's SQL Editor:

```sql
create table public.games (
  id bigint generated by default as identity primary key,
  name text not null,
  genre text not null
);

alter table public.games enable row level security;
grant select on public.games to anon;
create policy "Games are publicly readable"
  on public.games for select to anon using (true);

insert into public.games (name, genre) values
  ('Stardew Valley', 'Simulation'),
  ('Valorant', 'FPS'),
  ('Minecraft', 'Sandbox'),
  ('Overwatch 2', 'FPS');
```

The list uses anonymous reads. If an existing table returns no rows despite containing data, check its SELECT grant and row-level security policy for the `anon` role. Keep row-level security enabled and allow only the access you intend.
